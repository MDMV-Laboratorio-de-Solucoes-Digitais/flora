## Riscos / lacunas

- **Array inválido**: se o exemplo comentado for descomentado com aspas simples, vírgula sem aspas ou JSON malformado, o Figment `Env` falha ao extrair `Vec<String>` e o startup quebra. Mitigação: manter a linha **comentada** e usar aspas duplas internas idênticas a `.env.example:35`. `[NV]` não executado nesta avaliação.
- **base_url**: remover `FLORA_OIDC__REDIRECT_URI` não altera o callback — ele já vinha de `FLORA_APP__BASE_URL` (`auth.rs:101`). Operadores que acreditavam estar configurando o callback via `__REDIRECT_URI` devem ajustar `FLORA_APP__BASE_URL` ou listar a URI em `FLORA_OIDC__ALLOWED_REDIRECT_URIS`; `localhost` e `127.0.0.1` são origens distintas (`.env.example:31-32`).
- **Allowlist exata**: URIs extras precisam ser string idêntica à enviada no query `redirect_uri` (`auth.rs:106-112`); o callback derivado do base_url já é sempre aceito e não deve ser duplicado na lista (`oidc.rs:19`).
- `[NV]` **consumidores externos do template**: repositórios/scripts fora do checkout que copiam `.env.example` podem esperar `FLORA_OIDC__REDIRECT_URI` como chave funcional; não é verificável localmente. Compatibilidade de leitura preservada: sem `deny_unknown_fields`, um deploy que ainda exporta a chave antiga continua subindo (a chave é ignorada, como hoje).
- `[NV]` **CI**: `cargo check -p flora-core` e `python3 scripts/ci/check_gate_integrity.py` não leem `.env` em runtime (`.env.example:33-34`: "Export into the PROCESS ENVIRONMENT ... this checkout has no Rust code that auto-loads `.env`"); a edição é só de template, logo gate permanece PASS. Comandos registrados, não executados.
