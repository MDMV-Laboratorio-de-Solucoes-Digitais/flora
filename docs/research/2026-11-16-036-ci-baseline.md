## 5. What a new PR would need to show green

A new PR triggers `CI` and `Rust CI`. To be honestly green it must show **all four blocking
checks as success**:

1. `build` (workflow `CI`)
2. `build` (workflow `Rust CI`)
3. `db-tests` (workflow `Rust CI`)
4. `dependency-review` (workflow `Rust CI` — runs only on PRs; skipped on pushes)

The two informational checks — `supply-chain-vet` and `e2e-browser` (both `Rust CI`) — are
allowed to be red/skipped without blocking, but for honest evidence it is better to report their
actual status than to omit them. `docker-staging` and `OSV Scan` do not run on PRs and should not
be cited as PR gates. Because dev has no required status checks configured, "green" here is a
team convention, not an enforced merge restriction.
