### Why branch from `github/dev`

Local `dev` is 2 commits ahead of GitHub `dev` (`/metrics` endpoint, 49 lines). A branch off local `dev`
would make `gh pr diff` show those 49 lines plus the one-line fix, violating "one-line PR". Branching from
`github/dev` keeps the PR to the single workflow line. The uncommitted research/docs files are unrelated
and remain unstaged either way; they are never part of the PR.

## GitHub Actions behavior for this PR

- **Same-repo PR (head branch pushed to the `github` remote): yes, Actions run.** `pull_request` events
  fire for branches in the same repository; `GITHUB_TOKEN` has normal PR permissions and repository
  secrets are available (unlike fork PRs). Expect check contexts to sit at "Expected — Waiting for
  status to be reported" until the runs report.
- No workflow here uses `pull_request_target`, so workflows run against the PR merge ref with PR code —
  correct and safe for this trivial YAML change. `dependency-review` runs **only** on PRs
  (`if: github.event_name == 'pull_request'`, `fail-on-severity: moderate`, `fail-on-scopes: runtime`,
  `warn-only: false`).

## Gotchas

1. **Upstream trap:** local `dev` tracks `origin/dev` (Forgejo). A bare `git push` would push to the
   mirror; use `git push -u github <branch>` and `gh pr create --repo … --base dev`.
2. **Staging trap:** `OBJETIVO.md`/`ROADMAP.md` are already modified and many research docs are
   untracked. Never `git add -A`/`git add .`; always `git add -- .github/workflows/rust.yml` and inspect
   `git diff --cached` before committing.
3. **Diff-scope trap:** do not branch from local `dev` (2 extra commits, +49 lines) — branch from
   `github/dev` after `git fetch github dev`.
4. **Authority trap:** promoting any check to required, or editing branch protection/CODEOWNERS,
   requires explicit human admin authorization (research 031/032); out of scope for this PR.
5. **Verification:** after editing, re-validate YAML (`python3 -c "import yaml; yaml.safe_load(open('.github/workflows/rust.yml'))"`)
   and optionally dry-run `cargo test --workspace --no-run` locally before pushing.
